# Changelog

## 2.0.0-alpha.1 — 2026-10-19

- Fixes from the release checklist: the top bar fits the window at any editor size (at 125% and 150% in MZ's 816 × 624 window, More, Save and Done were off its edge): the words under the tools go first, then it takes a second row. Games without Aseprite gear no longer log a failed request for `data/DocsDoodadsAseprite.json` on every start (desktop games look for it first).
- Templates, presets and saving: More → Templates renames, re-sorts and deletes your own event templates (saving one under a name in use asks first), and packs carry them. More → Map Settings copies some or all of another map's settings (one map's ground only if asked) as one undo step, and keeps settings as presets. Ctrl+click and Shift+click pick several items in the Item Bag to tag, favourite, add to a collection, move to another folder (updating what uses them) or delete if unused (into the editor's bin). Steps keeps named checkpoints of a map through Save and closing, restored as one undo step. Save This Map saves one map, and Autosave (More) saves every 5, 10 or 20 minutes of unsaved work. Packs bring in a zip of art, or a pack inside a zip, with the same checks on where files may go.
- Finding and picking: Find (More, or the palette) searches this map or all maps by picture, Name, `tag:`, `name:`, `layer:`, `has:` (light, sound, collision, states, touch, particles) and `is:` (locked, hidden, conditional), a leading - leaving out; Pick All, Hide, Show, Lock and Unlock act on all it found as one undo step. The Outliner lists this map's doodads by layer with Hide, Lock and Solo per row. Ctrl+drag picks what the box touches and Alt+drag draws a lasso; "Pick doodads in a region..." picks those standing in a region. With several picked: Snap to Grid, rows or columns some pixels apart, and Ctrl+arrows move them a tile where the ground lets them stand.
- Movement, collision, light and camera: a doodad's collision can stop only the player or only events, be crossed one way (a ledge), and change shape with its state (an open gate keeps its posts). Events swim with `<docs swim>` and fly with `<docs fly>`; taking off, landing and diving can run common events, landing can be kept below a terrain height, and move routes can `this.docsJump()`. Clicking where the player can't go shows a cross; clicking a touchable doodad walks up and touches it; each map can have its own click marker. Doodads with collision and events marked `<block light>` (doors) stop light; a light can need a switch or a condition. 2D Camera Follow → Nothing now holds the camera while the player moves; Zoom to Point zooms on a tile or a character. In 3D, doodads beyond "Plain beyond" tiles are drawn without shadows or effects. Each save writes the files the plugin draws to `data/DocsDoodadsRequired.json`, and `npm run deploy -- --restore` puts them back into a deployment made with "Exclude unused files".
- For events: a calendar on the running clock (day 1, 2, 3..., weekdays by name, named dates, day and weekday variables, the Calendar command, `api.day()` and friends); the clock can run in battles and menus, and a battle can take some minutes. A state can play a sound and an effect when a doodad goes into it and go back after some seconds (a trap that resets); Set Doodad State can wait for the crossfade. A touch can run only once (the save remembers), wait between touches, and show a prompt (Open, Read, !) while the player faces it. Play Doodad Animation plays a strip once, now, with `animationEnd` for scripts. Explored Map reveals a region and puts how much is explored in a variable. `api.place` and `api.remove` take a transition, and removing no longer rebuilds the map's other doodads. The API covers the plugin commands: `touch`, `resetTouch`, `playAnimation`, `setWind`, `flashlight`, `traversal`, `traversalAction`, `playVfx`, `reveal`, `explored`, `feature`.
- Project and release: one version (2.0.0-alpha.1) in package.json, the plugin header, the editor and the changelog, checked by `npm run verify` along with What's New (new items for this version), the translation template (`npm run strings -- --check`) and ESLint (`npm run lint`). Each test suite runs in a folder of its own and verify fails if one changes the repository. The coverage gate is 85/85/80/75 (91 % of lines covered), Cut Up Sheet and Save as PNGs have a suite of their own, the suites' time budgets follow the machine's speed, and CI runs them once per system. The guide lists Doodad JSON Formatting, the cheat sheet `[bN]` and `[hN]`, SECURITY.md says that doodad conditions are code, README and the header describe More's twenty-odd entries, and CONTRIBUTING.md has a release checklist. `.gitignore` covers what the plugin writes into a project.
- Problems lists doodads whose condition isn't JavaScript that runs (they always show), with Remove Condition.
- Fixes: undoing a delete of several doodads puts them back in their places (picked out of order, they came back reordered); undoing a placement after going to another map no longer puts the doodad there; undoing the delete of an event no longer shows one the game had erased; the drag ghost no longer reloads its picture on every mouse move; + and − are only taken from the game while zooming by keys is on.
- A quicker editor. The crash snapshot is written only when something changed since the last one, without holding up the editor (a save meanwhile wins). The Item Bag's library is written a moment after a change (a favourite, tags, a collection, collision) and on Save or closing, compact (about 40 % smaller). Key presses no longer read the saved keys for every shortcut. Where-used reads a map or database file again only when it changed on disk. Bringing in files indexes those files instead of every folder (here 0.5 s instead of 12 s), a dropped folder is walked once, and same-sized files are compared a piece at a time. The map panel's list of doodad pictures is filled when a field wants it, the packing note is checked every few seconds, thumbnails are read from disk in the background and the cache keeps one per item (up to 3,000), and Save backs up only the files it changes.
- Faster maps with many doodads. Doodads off the screen (or off the 3D view) are not drawn, and their shadows, filters and effects wait; their lights still shine. On a 200 × 200 map with 3,000 doodads and 375 lights this took Show Speed from 23 to 60 frames a second on the flat map (12,000 draw calls a frame to 150) and from 14 to 60 in 3D (24,000 to 248). Per doodad and frame, the game no longer rebuilds the layer list, the season, the filter signature or a light's settings; a character's step checks the doodads on that tile instead of all of them; light masks are traced once and moved with the map; post-processing, visual equipment and the ambience around the player are worked out again only when what they depend on changes; characters' frames no longer make a new texture each time (they were never let go).
- Memao creator: the export stands characters on the tile's bottom (every frame 6 pixels lower, as MZ's own characters; on at first, a sheet that would lose pixels stays as it was and is named), and a pack with more than one prop of a kind gets a row in Tools to choose it.
- MZ creator: a part offers every colour slot its walking and battler pictures use, not only its face's (108 parts gain one, such as a cloak's second colour).
- Character creators: Export recipe... and Import recipe... (under Load) keep one character in a file of its own anywhere on the computer; a recipe from another creator says which to switch to.
- Character creators: a list beside the window's title switches between the libraries scanned (MZ, LPC, Memao), keeping the name and each library's character. The palette has two entries, Characters (the card) and Character Creator... (the one used last), in place of four. The Characters card has a group per library that stays folded or open as left. The export picks the face slot from the face sheet's eight faces as they are now. Under High contrast the window is black on white with 3-pixel borders.
- Character creators: a padlock on each row (or L) keeps it through the dice (an MZ part with its colours). The body dice keep the body type and give a new face and hair (the LPC ones only ever gave male or female, losing a chosen teen, child, muscular or pregnant body); Shift+X also rolls the type, among those the library has and the locked parts fit. Ctrl+Z goes back a step, the last 20. On a gamepad: hold X for a new type, Y with a direction locks, Back with B undoes (X, Y and Back alone now act when let go).
- Memao creator: long hair, side hair and eyebrows take the hair's colour, shown by a chain in place of their swatch; click it (or K) for a colour of their own, and again to link back.
- Character creators: click a row's value (or press Enter on the row) for all its choices in a grid of pictures, None first and the one worn marked. Typing finds one by name, the arrows move, Enter picks, Esc clears what was typed and then closes; on a gamepad the right stick opens it, the d-pad moves, A picks and B closes. Each picture is the part on its own, standing and facing down (MZ: the generator's own icons), drawn once per part and body type as it scrolls into view, so a long row opens at once and fills in.
- Character creators: a new colour no longer reads and unpacks the library's pictures again (each kit keeps its decoded files within a memory budget: LPC 96 MB, Memao 160 MB, MZ 96 MB), an MZ skin colour no longer redraws clothing with no skin in it, and the LPC credits no longer draw the walk a second time.
- MZ creator: mask colours a step off a colour slot's key (a few of MZ's own masks have them) take that slot's colour when the part uses that slot, so a recoloured part keeps no stray pixels; colours that are no slot keep their colour and the scan lists them. The generator folder is found from MZ on macOS too.
- Character creators: Tab and Shift+Tab move between the buttons (the other side is now `[` or `]`), the focus stays on the button pressed, and screen readers hear what changed ("Hair: Emo Left, 12 of 40"). A part with several colours (MZ's Clothing 2–4, LPC's eyes) shows which one the swatch is on; `C` (or holding the pad's A) goes to the next, and Shift+arrows change it. The window follows its size, and the row being changed stays in view.
- Export again: the "Replace" question says which face of the face sheet changes (and leaves the face out when that slot is empty), and lists the Visual Equipment part sheets it would replace.
- A saved character whose parts are gone loads without them (they are named), and a slot that needs a part takes the nearest. The creators' row labels are in the translation template.
- Rebuild Index asks first and keeps what you set on each item (tags, favourites, collections, cut-up pieces, collision, placement and use counts); before, it wiped them. Opening the editor reads the Item Bag's library again only when the file changed, and what was picked follows it.

- Cut Up Sheet: Save Pieces makes the item's picture in the Item Bag again; closing it (Close, Esc or closing the editor) with pieces not saved asks; Undo, Redo and Duplicate follow your keys; clicking a piece without moving it is no longer an undo step.

After going to another map, new doodads go on Main unless that map has the layer that was picked. Bring Forward, Send Backward, Bring to Front and Send to Back in the right-click menu act on everything picked.

A mouse press hides the ring until the keys move focus again.
- The right-click menu is a menu for the keyboard and screen readers: it takes the focus, the arrow keys (Home, End) move, Enter runs, Esc or Tab closes and gives the focus back, and the arrows no longer also nudge the selection. Undo and Redo say when there is nothing to take back.
- The Item Bag's kinds are tabs (the arrow keys show the next one), and the edges of the Item Bag and Details resize with the arrow keys (Shift for 50 pixels, Home and End).
- Screen-reader names are given only to what was just added, instead of going over the whole editor after every change.
- Sound effects keep their authored pitch and volume: random variation is off by default (set *Pitch variation* and *Volume variation* to turn it on), only applies to map events and the party, and never to sounds in battles, menus or common events without a map event. `<no variance>` opts an event out. Play SE is wrapped instead of replaced, so plugins that change it keep working.
- The day/night clock is only stored in the save once it runs (or Set Time moves it), so saves made with day and night off carry no clock, and the start hour isn't frozen by an early read. Setting an earlier hour keeps the day; Pass Time past midnight starts the next one; Set Time of Day and `api.setTime(h, m, day)` can set the day.
- Doodad states and lights on another map: `WorldState.light` and `state` read that map's doodads, Set Doodad State refuses a state the doodad doesn't have (the console lists the ones it has), and Store Doodad State takes a map.
- Touchable doodads answer across a counter, as events do; the touch payload (`touched()` and `api.on('touch')`) says which tile.
- `api.place` with only a width, and `api.set({ art })`, size the doodad from its picture; `api.remove` removes from one map only. Set Visual Color matches parts in any case. A deleted event template is reported instead of quietly making an NPC.
- Sliding on ice waits while a message is open or an event runs. A jump over a looping map's edge lands on the map. Dive checks the other map exists and keeps the player inside it. Boats and ships sail past doodads unless one is set to **Blocks boats and ships** (Details). The destination marker wraps MZ's own update.

- Keyboard shortcuts come from one table: More > Keys (or Keyboard Shortcuts in the palette, or ?) lists every key by group and changes any of them: click a key, press the new keys, Esc keeps the old ones. A key already in use asks before it moves; the editor key, Esc and the arrows can't be taken. Tools and views (Stamp, Hills, Show Collision...) can be given keys too. Tooltips, menus and the palette show your keys; they are kept on this computer. Letters follow the keyboard layout (Ctrl+Z is the key marked Z on AZERTY). Copies keep their id, lock and editor-hidden flag through a sync. A selection holding a whole copy of another prefab saves it inside the new prefab: syncing the inner prefab changes the copies of every prefab that holds it, and deleting it leaves its doodads in them.
- Screen Looks by time and by region: game-wide looks that ease in and out between two times of day (a warm dusk, a blue night), and looks that fade in while the player stands on a region (game-wide, or a map's own, which win for the same region: a cold crypt), each a preset or a copy of the look being edited, with a strength. - Traversal on gamepads and touch screens: jump and fly go on gamepad buttons MZ leaves free (the triggers by default), and touch screens get round on-screen Jump (or Dive) and Fly (or Land) buttons in the corner; World > Traversal picks the buttons, when the on-screen ones show, and their size.
- Doodad data saves with its keys in a fixed order, so saving the same map gives the same file. The plugin parameter **Doodad Files: One file per map** keeps each map's doodads in its own file under `data/DocsDoodads/` for smaller diffs and fewer merge conflicts in Git; maps that lose all their doodads lose their file (after a backup).
- Doodad states (Details > States): named looks for one doodad (lit and unlit, open and closed, whole and broken), each with its own art, and with or without its light and collision. A switch, a variable or events pick the state; the old picture crossfades into the new. Preview shows each state while editing.
- World state in saves: the plugin commands Set Doodad State, Set Doodad Light and Store Doodad State, and `DocsDoodads.WorldState` for scripts (`is('Front Door', 'Open')`), find doodads by the Name given in Details and keep what they set with the save file. A saved state wins over the switch or variable until it is cleared.
- Touchable doodads (Details > Touch): a common event runs when the player presses Action facing the doodad (or clicks it), or walks into it, and it can step to its next state on its own (a door that opens and closes). Problems lists state art and common events that are missing.
- Problems (More, or the palette) lists what is probably a mistake, on this map or every map: pictures and sounds that aren't in the project, doodads standing outside the map, lamps on maps that never get dark, events nobody can step on, and events under a doodad's collision. Each has Go To (it centres the map and picks the doodad or event, going to another map first if needed) and, where safe, a Fix (Replace Art, Remove Sound, Move Inside), each one undo step.
- Check Reach floods the tiles the player can walk to from where they stand (or from a clicked tile), through walls, doodad collision and characters in the way, shades them on the map, and lists the doors, chests and transfers out of reach, noting when only a character is in the way.
