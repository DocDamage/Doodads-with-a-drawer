## 1.2 3D performance

Big World, 150 doodads (about 20 lit lamps), terrain on, ambient darkness 0.55, the player walking. Frame rate over 5–6 s.

| Case | Before this branch | After |
| :--- | ---: | ---: |
| View 40, clear | 57 fps | 59 fps |
| View 40, storm 9 | 56 fps (p95 33 ms) | 56–59 fps (p95 17–33 ms) |
| View 64, storm 9 | **18 fps** (p95 100 ms) | **54–58 fps** (p95 17–33 ms) |
| View 64, storm 9, slow CPU, High | | 13–16 fps |
| View 64, storm 9, slow CPU, Medium | | 33–57 fps |
| View 64, storm 9, slow CPU, Low | | 48–56 fps |
| View 40, storm 9, slow CPU, High | | 20 fps (56 fps with terrain off) |

Frame rates on this machine vary by up to ±15% between runs; a back-to-back run of the performance commit and the final build gave 55.2 and 56.5 fps (normal CPU) and 15.2 and 15.4 fps (slow CPU), so the features added after the performance work cost nothing measurable.

Terrain was the cost: per-frame allocation, `Array.sort` on tens of thousands of triangles, a full mesh rebuild on every tile step, and settings that were re-read and JSON-stringified many times a frame. Fixed in this branch. On a slow CPU, High at long view distances is still heavy; that is what the new Medium and Low **Effects Quality** levels are for.

## Bugs found and fixed

1. **Crash after the menu on maps with glowing lamps** ("Cannot read property 'valid' of null"). MZ destroys every texture of the scene it leaves; the light glow, particle shapes and 3D weather textures were shared between scenes. In `main` before this branch; affects 2D maps too.
2. **Crash after a map transfer or save load** ("Cannot read property 'uvsFloat32' of null"), the same cause. The next map scene is built before the old one is destroyed, so it picked up textures that were about to be destroyed.
3. **Effekseer animations in 3D played off to one side** (at the target's flat-map position) and kept full size at any distance.
4. **The flying airship in 3D was sorted as if a tile north** (trees beside the player hid it), and its shadow stood up instead of lying flat.

Seen once and not reproduced: a request for a file named `undefined` alongside crash 2. It did not recur after the fix.

Not a plugin bug: on the first battle after a page reload, started from the DevTools console, enemies were not drawn; the same happens with the plugin switched off. Normal battles show them.

## Review fixes

A code review and a playtest of this branch (Starting Town, Field Map, a battle, the globe, the menu) found the following, now fixed. `scratch/test_engine_lifecycle.js` covers them, and a second playtest checked them in the engine.

- **Memory held after leaving a 3D map:** the terrain mesh, the lighting texture, the sky gradient, the standing tile pictures and the minimap picture. Also: the battle background (one per battle), the world map (a new picture every frame while the globe turned), and the snow cap cache (dropped without freeing at 64).
- **Models:**
  - Parts using the same image share one texture, and Blob URLs are freed.
  - `data:` image URIs load.
  - Mirrored nodes keep their faces facing out; normals are right under uneven scaling.
  - Models load when the map is set up, not mid-frame.
  - A still camera reuses the last frame's triangles.
  - A model that failed is tried again after 5 seconds.
  - Models, and the files they point to, have to be inside the project folder.
  - Old parts are freed when a model changes.
- **Ledges** no longer jump vehicles, the party aboard one, or Through characters. Passability checks use the terrain kept for the frame (pathfinding asks thousands of times).
- **See-Through in 3D:**
  - The flat fade and the flat silhouette no longer run on top of the 3D fade.
  - Nothing fades while editing.
  - The 3D view has no silhouette, so Silhouette mode fades there.
- **Effekseer:** a target not drawn this frame (hidden, blinking) no longer pulls the animation to where it was last drawn.
- **Standing tiles** keep the same sprite per object while the camera moves, so a fade stays with its tree.
- **Snow cover** keeps off water even when the 3D water setting is off.
- **The undo history panel** closes with the editor.
- **Make Layer Sheets:**
  - Layers with the same name get `_2`, `_3`.
  - Existing sheets are replaced only after asking.
- **The build** fails on a `.js` file in `src/` without the `NN_` prefix, instead of leaving it out.
- **Cloud size** now defaults to 6 tiles. At 12, the shadows were too large to notice.
