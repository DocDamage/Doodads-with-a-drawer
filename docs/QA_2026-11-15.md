# QA Record, 15 November 2026

## Map pictures (7.2.4)

Tested in a disposable copy of `rpgmaker project`, leaving the source project unchanged. The core renderer was checked at `24ea129`; subsequent cache and UI corrections were checked through `fd6b687`. The renderer itself did not change during those corrections.

### Setup

- RPG Maker MZ 1.10.0, NW.js 0.48.4, Chromium 85.0.4183.121, Windows.
- Game viewport approximately 816 x 624 CSS pixels, device pixel ratio 1.5.
- Interior (map 1), town (3), looping field (4), cave (5), and a disposable wide variant of the field (6).
- Sample story events were disabled in the disposable maps so dialogue would not interrupt map transfers.
- Checks used the real editor functions and game loop through DevTools, F10, keyboard input and mouse hover. Screenshots of World View and tab previews were inspected.

### Rendering and navigation

| Map | Map size | Picture size | Result |
|---|---|---|---|
| Interior | 17 x 19 tiles | 229 x 256 pixels | Pass |
| Town | 35 x 40 | 224 x 256 | Pass |
| Looping field | 30 x 60 | 128 x 256 | Pass |
| Cave | 34 x 40 | 218 x 256 | Pass |
| Wide looping field | 60 x 30 | 256 x 128 | Pass |

- Tiles and placed doodads appear in the pictures. No full-map canvas is allocated.
- Interior, town, looping field and cave were checked flat and with the live 3D view and a storm enabled. PNG bytes were identical between those modes; camera coordinates and 3D settings were unchanged by capture.
- Forced refreshes after map load took approximately 41-101 ms on this machine, with work yielding between slices. These figures cover the maps above, not a general large-map benchmark.
- Actual mouse hover showed the town picture in its map-tab tooltip. Keyboard search for Go to map showed pictures and accessible named placeholders in the command palette.
- World View displayed the town, cave and wide/tall fields in their linked positions. The selected-map preview updated when its picture completed.
- Map 2 was never opened and acquired no PNG. Making a source map file newer than its PNG made the cache stale; opening/requesting the current map regenerated it.
- No game error appeared during these checks.

### Cache, saves and discard

- Copied a doodad from map 1 to map 3. Although the target was not in the persistence layer's touched-map list, its unsaved picture remained memory-only. Its saved PNG bytes were unchanged; discard cleared the temporary picture.
- Saved a cross-map copy on map 1. Map 3's own MZ JSON did not change, but its old PNG was invalidated. The selected map preview became a placeholder immediately; a World View pixel check confirmed the old map image was cleared. Visiting map 3 regenerated its picture.
- An unaffected field PNG remained byte-for-byte unchanged.
- A simulated failed save returned failure and preserved the target and unaffected PNGs. Discard then left no unsaved work.
- Focused regressions additionally cover selective Save This Map success/failure, asynchronous replacement jobs, deferred old image loads and cache-file deletion failures. Cache errors do not turn a successful project save into a failed save.

## One Settings page (7.2.6)

Tested in the same disposable project and MZ/NW.js/Chromium versions above. The final production build was `08204d6`; subsequent commit `b5abd4e` corrects test expectations and temporary-working-directory isolation only. The source game project was unchanged.

### Search and navigation

- More → Settings and Ctrl+, open the grouped, searchable card and focus its search field. The test project exposes 328 settings, including all 16 plugin parameters.
- Opening, indexing and searching preserve the selected doodads, undo history, dirty state and exact project JSON. Escape closes the card without changing the selection.
- Searching for shadows and pressing Enter opens the live map control, unfolds the inspector and its details, clears the map-panel search, focuses the target and flashes its outline. Selecting a map setting deliberately clears the object selection so the map inspector can appear.
- Forced-closed 3D fog, world shadow opacity and extension minimap sections open and focus correctly. The final visibility guard also rejects truly hidden or disabled controls.
- Autosave opens and focuses its visible control in both the folded More menu and the separate Map menu.
- Look → Theme, rebindable Undo, and fixed Nudge/Cancel key descriptions resolve to their live targets. Ctrl+K with `Setting: theme` opens Look and focuses Theme.
- Navigation works on the interior, town, looping field and cave. A descriptor retained across a map transfer resolves the current map's live control rather than a detached element.
- Select-setting captions contain their setting names without option captions or truncated HTML fragments.

### Plugin parameters and runtime

- Parameters display configured and default values with the guidance “Change in MZ's Plugin Manager”. The test project's grid width displays configured `48` and default `0`; its row contains no editable controls.
- Checks used real MZ editor functions and keyboard events through DevTools. During the final hidden-window replay, the QA harness advanced MZ's scene-update loop because native animation frames were suspended; this was confined to the disposable runtime.
- No game error appeared, and the project remained clean after navigation. The disposable MZ process was stopped after testing.

- `npm audit`: zero vulnerabilities.
